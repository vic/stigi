Stigi sits among many fine languages, and it learns from each of them. These are the agent-oriented languages, the effect and memory work, and the established languages around it.

## Agent-oriented languages

- [Achuk](https://github.com/LambdaQ-Labs/achuk) — code-as-database symbol index. Stigi keeps code in a database too, addressed by content hash.
- [agentlanguages](https://github.com/aallan/agentlanguages) — catalog of agent languages. A helpful map of this space, and Stigi appears among its neighbors.
- [AISP](https://github.com/bar181/aisp-open-core) — structured specification format for AI. Stigi writes specifications as typed code that the checker reads.
- [Chaos Intelligence](https://github.com/Cattmonkey/ChaosIntelligence) — agent-native functional language. Stigi is also functional at its core and agent-native by design.
- [Codong](https://duckduckgo.com/?q=Codong) — agent-first language. Stigi follows the same agent-first idea and adds proof-carrying checks.
- [Fortis](https://duckduckgo.com/?q=Fortis) — effects and contracts language. Stigi follows the same effects-and-contracts path.
- [Glyph](https://duckduckgo.com/?q=Glyph) — language with effects in signatures and contracts. Stigi puts effects in signatures and contracts too.
- [GlyphLang](https://duckduckgo.com/?q=GlyphLang) — glyph-syntax language for agents. Stigi shares the idea of a compact syntax for agents, and keeps names readable.
- [Harn](https://github.com/burin-labs/harn) — agent language with replay. Stigi also replays runs, and records them as part of the proof trail.
- [ilo](https://github.com/ilo-lang/ilo) — agent-first language. Stigi shares the goal of syntax that agents read and write well, and adds a content-addressed store and checked proofs.
- [iyi](https://github.com/iyilang/iyi) — constrained, Crystal-compatible language. Stigi also limits the language so that agent output stays checkable.
- [Kavach](https://duckduckgo.com/?q=Kavach) — per-function capability declarations. Stigi declares capabilities per function as well, and checks them as types.
- [Lattice](https://duckduckgo.com/?q=Lattice) — language with canonical syntax and effect rows. Stigi has one canonical printed form and effect rows too.
- [lugh-lang](https://duckduckgo.com/?q=lugh-lang) — effects and contracts language. Stigi follows the same effects-and-contracts path.
- [MoonBit](https://www.moonbitlang.com/) — AI-native general-purpose language. Stigi shares the focus on AI-written code, and goes further with proofs.
- [Neo](https://duckduckgo.com/?q=Neo) — language for AI-written code. Stigi shares the aim of making AI-written code safe to accept.
- [Nexa](https://github.com/Nexa-Language/Nexa) — language for open programs and durable agent runs. Stigi also makes agent runs durable, using replayable frames.
- [Nudge](https://github.com/NekomyaDev/nudge) — budget-aware agent language with traces. Stigi tracks cost and traces too, and checks budgets at compile time.
- [Rul](https://github.com/rul-lang/rul) — 128-bit agent instruction format. Stigi shares the wish for small, fixed-size instructions.
- [Sema](https://github.com/sema-lisp/sema) — Lisp with agent primitives. Stigi keeps agent actions as typed effects rather than library calls.
- [Semaprax](https://github.com/wavect/semaprax) — agent-facing systems language with a semantic graph. Stigi shares the semantic-graph view of code and targets portable C.
- [Shio](https://duckduckgo.com/?q=Shio) — language for AI-written code. Stigi shares the aim of making AI-written code safe to accept.
- [SSPUR](https://github.com/sspurlang/sspur) — typed agent language on a content-addressed graph. Stigi also stores code as a content-addressed graph, and ties each result to a checked proof.
- [Tessera](https://duckduckgo.com/?q=Tessera) — effects and contracts language. Stigi follows the same effects-and-contracts path.
- [Vera](https://github.com/aallan/vera) — language for LLM-written code with call-site contracts. Stigi checks contracts at call sites as well.
- [x07](https://github.com/x07lang/x07) — agent language with a JSON AST. Stigi also gives agents a structured tree form, and keeps a readable text form next to it.

## Effects, memory and ownership

- [Ante](https://antelang.org/) — refinement-typed language. Stigi also uses refinement types for index and size facts.
- [ASAP](https://duckduckgo.com/?q=ASAP+as+static+as+possible+memory+management) — static memory management. Stigi shares the goal of memory handled at compile time.
- [Austral](https://austral-lang.org/) — language with linear types and capabilities. Stigi shares the use of linearity and capabilities to rule out misuse.
- [Bend](https://github.com/HigherOrderCo/Bend) — parallel language on the HVM runtime. Stigi shares the interest in parallel-by-default evaluation.
- [Bend 2](https://github.com/bendlang/bend) — linear proof language for GPU and CPU. Stigi also mixes linear types with proofs.
- [Calx](https://github.com/ellipog/calx) — memory-safe language that compiles to C. Stigi takes the same route to C and adds proofs.
- [CeeSafe](https://github.com/CeeSafe/CeeSafe) — ownership-based memory-safe language that emits C11. Stigi also emits portable C and keeps memory safe by types.
- [DRFCaml](https://duckduckgo.com/?q=DRFCaml) — data-race-free OCaml variant. Stigi shares the goal of data-race freedom by types.
- [Effekt](https://effekt-lang.org/) — language with effect handlers and capabilities. Stigi uses effect handlers with capabilities in the same spirit.
- [Hylo](https://github.com/hylo-lang/hylo) — systems language with value semantics. Stigi shares the aim of safe memory without a garbage collector.
- [Koka](https://github.com/koka-lang/koka) — algebraic effects language that compiles to C. Stigi also compiles effects down to C.
- [Kyo](https://github.com/getkyo/kyo) — effect library for Scala. Stigi shares its view of effects as a small kernel.
- [OxCaml](https://github.com/oxcaml/oxcaml) — OCaml extension with modes. Stigi reaches data-race freedom with a single-writer rule.
- [Perceus](https://duckduckgo.com/?q=Perceus+garbage+free+reference+counting) — reference counting with reuse. Stigi learns from its reuse of freed cells.
- [Roc](https://github.com/roc-lang/roc) — functional language with fast compiled output. Stigi shares the aim of a small functional language that runs fast.
- [V](https://github.com/vlang/v) — general-purpose language that compiles to C. Stigi compiles to C too.
- [Vale](https://github.com/ValeLang/Vale) — memory-safe systems language. Stigi also seeks memory safety without a collector.

## Established languages

- [C++](https://isocpp.org/) — systems language. Stigi gives similar speed with stricter safety.
- [Carbon](https://github.com/carbon-language/carbon-lang) — C++ successor language. Stigi shares the goal of a gentler path from C-family code.
- [Erlang](https://www.erlang.org/) — actor-based functional language. Stigi shares its pattern matching and message passing.
- [Go](https://go.dev/) — systems language with a garbage collector. Stigi borrows its small, readable style.
- [Haskell](https://www.haskell.org/) — functional language with strong types. Stigi shares its care for types and purity.
- [Kotlin](https://kotlinlang.org/) — JVM language. Stigi reads like a modern typed language in the same family.
- [Mojo](https://www.modular.com/mojo) — Python-syntax systems language. Stigi also pairs friendly syntax with systems speed.
- [OCaml](https://ocaml.org/) — functional language with modules. Stigi shares its mix of functional style and speed.
- [Python](https://www.python.org/) — dynamic language. Stigi keeps a readable surface that Python users find familiar.
- [Rust](https://www.rust-lang.org/) — systems language with ownership. Stigi shares the goal of memory safety, and checks it with types and proofs.
- [Scala 3](https://www.scala-lang.org/) — language with optional braces. Stigi takes its surface style from Scala 3.
- [TypeScript](https://www.typescriptlang.org/) — typed JavaScript. Stigi reads as a typed language in the same spirit.
- [Zig](https://ziglang.org/) — systems language. Stigi shares its direct, explicit style.

## Live and content-addressed

- [Hazelnut](https://hazel.org/) — live programming with typed holes. Stigi also has typed holes, filled by checked synthesis.
- [Hoogle](https://hoogle.haskell.org/) — search by type for Haskell. Stigi supports search by type as well.
- [Newspeak](https://newspeaklanguage.org/) — object-capability live language. Stigi shares its capability model.
- [Pydantic](https://pydantic.dev/) — data validation for Python. Stigi checks data shapes at the boundary too.
- [Smalltalk](https://pharo.org/) — live object environment. Stigi keeps the same feeling of a live, queryable program.
- [Unison](https://www.unison-lang.org/) — content-addressed functional language. Stigi also stores code by hash, so names are only labels.
